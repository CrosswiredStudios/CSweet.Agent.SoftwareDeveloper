# 2.2.0

Moves to `CSweet.Agent.SDK` 5.20.0 (was 5.12.1). No agent code changed.

The reason for the move is Git delivery. With SDK 5.20.0 the workspace calls this agent already makes deliver with git when the platform names a work branch for the assignment: preparing the workspace clones the repository, each save commits and pushes the work branch, a checkpoint before a larger runtime is a pushed commit, and inspection and publication name that commit. Whole-workspace archives are no longer downloaded or uploaded for such a workspace, and `node_modules/`, `.venv/` and anything the repository's `.gitignore` excludes are never sent.

Nothing changes until the platform operator turns Git delivery on (`CSweet:SourceControl:WorkspaceSync:AgentGitDelivery`). With it off, on GitHub-connected repositories and for personal work, the agent uses snapshots exactly as 2.1.15 did.

Things that differ under Git delivery:

- Each save that finds changes is a commit titled `chore(wip): save work in progress`, attributed to the agent's employee identity. The publish commit message is unused. These commits stay on the work branch.
- The coding model's shell sees a `.git` directory in the assignment workspace. It can run local git commands; it cannot push.
- The runtime image must contain git 2.31 or later.

No manifest, capability, grant or configuration change.

Also moves `CSweet.WorkManagement.Contracts` to 5.4.0 (was 5.3.0), which SDK 5.20.0 requires. This agent does not use what 5.4.0 added.
