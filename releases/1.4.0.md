# 1.4.0

- Accept general software requests in chat and ask who will create tickets when the request does not say. Decisions and source requests survive restarts without duplicate tasks.
- Create an owned personal ticket and private C-Sweet repository, invoke the configured coding model, test and publish custom application source, then build and run its Dockerfile in isolated Linux compute.
- Return a health-checked application link, source link, commit and expiry. Known build failures get bounded coding-model repairs; uncertain outcomes remain visible blockers.
- Use SDK 3.43.0's typed personal Git workspace API and durable operating state. Approve the new personal-work, state read/write and user-input declarations in the normal agent upgrade review.
- Local test-link networking requires an explicit business-owner grant for the instance and port. Installation approval does not grant networking.
- Requires the matching Core update and Docker-ready Linux image. Core handles preparation and UAC automatically, waiting for old instances to finish teardown before upgrading the provider image.

MVP limits: local compute-host links, cached Python/Node Docker bases, 16 MiB source bundles, 30-second guest commands and one-hour ephemeral instances. Outbound dependencies, public internet deployment and long builds remain unsupported. Existing assigned-work behavior and production authority are unchanged.
